AssetPlus is intended to be used by a hotel manager to manage the maintenance of hotel assets. The manager can track specific assets in the hotel, categorize them by asset type, raise maintenance tickets when issues arise, and oversee the resolution of those tickets. Hotel staff (employees and the manager) can add notes and images to maintenance tickets. Guests and employees can also raise maintenance tickets to report issues.

The application has a built-in user account for the manager called manager@ap.com. Initially, the password for this account is set to manager, but this can be changed later by the person with manager access. When updating the manager password, the new password must be at least four characters long, must contain one character out of !, #, or $, must contain one lower-case character, and must contain one upper-case character. The password cannot be empty.

Employees can register an account in the system by providing an email, password, name, and phone number. The name and phone number are optional fields. The email must not be empty, must not contain any spaces, must be a valid email address, and must use the domain @ap.com. The email cannot be manager@ap.com and cannot already be linked to an existing employee account. The password cannot be empty. Employees can update their own account information, changing their password, name, and phone number. The password cannot be empty when updating. Employees can also delete their own account. If an employee account linked to a given email does not exist in the system, the deletion request has no effect. If the email corresponds to the manager account, the manager account is not affected and remains in the system.

Guests can register an account in the system by providing an email, password, name, and phone number. The name and phone number are optional fields. The email must not be empty, must not contain any spaces, and must be a valid email address. The email cannot be manager@ap.com, cannot use the domain @ap.com, and cannot already be linked to an existing guest account. The password cannot be empty. Guests can update their own account information, changing their password, name, and phone number. The password cannot be empty when updating. Guests can also delete their own account. If a guest account linked to a given email does not exist in the system, the deletion request has no effect. If the email corresponds to the manager account, the manager account is not affected and remains in the system.

The manager can add asset types to the system. Each asset type has a name and an expected life span measured in days. The name must not be empty, and an asset type with the same name must not already exist in the system. The expected life span must be greater than 0 days. The manager can update an existing asset type, changing its name and expected life span. The same validation rules apply: the name must not be empty, the expected life span must be greater than 0 days, and the new name must not already belong to another asset type in the system. If the asset type being updated does not exist in the system, an error is raised. The manager can delete an asset type from the system by name. If the specified asset type does not exist, the deletion request has no effect.

The manager can add specific assets to the system. Each asset has a unique asset number, a type (which must correspond to an existing asset type), a purchase date, a floor number, and a room number. The asset number must not be less than 1. The floor number must not be less than 0. The room number must not be less than -1. If the specified asset type does not exist, the asset cannot be added. The manager can update an existing asset, changing its type, purchase date, floor number, and room number. The same validation rules apply: the asset type must exist, the floor number must not be less than 0, and the room number must not be less than -1. The manager can delete an asset from the system by its asset number. If the specified asset does not exist, the deletion request has no effect.

Any user — a guest, an employee, or the manager — can raise a maintenance ticket in the system. Each ticket has a unique id, a ticket raiser identified by their email, a date the ticket was raised, a description, and an optionally associated asset number. The ticket description cannot be empty. The ticket id must not already exist in the system. The ticket raiser must correspond to an existing user in the system. If an asset number is provided, it must correspond to an existing asset. Tickets can also be raised without any associated asset. The manager can update a maintenance ticket, changing its ticket raiser, date, description, and associated asset. The same validation rules apply when updating: the description cannot be empty, the ticket raiser must exist in the system, and if an asset number is provided it must correspond to an existing asset. The asset can also be removed from a ticket during an update. The manager can delete a maintenance ticket from the system by its id. If the specified ticket does not exist, the deletion request has no effect.

Hotel staff — employees and the manager — can add maintenance notes to existing tickets. Each note has a note taker identified by their email, a date, and a description. The note taker must be an existing hotel staff member. The ticket the note is being added to must exist in the system. The ticket description cannot be empty. The manager can update an existing note on a maintenance ticket, changing the note taker, date, and description. The same validation rules apply: the note taker must be an existing hotel staff member, the ticket must exist, the note being updated must exist for that ticket, and the ticket description cannot be empty. The manager can delete a note from a maintenance ticket by note index and ticket id. If the specified note does not exist for the given ticket, or if the specified ticket does not exist, the deletion request has no effect.

Hotel staff can add images to maintenance tickets. Each image is identified by a URL and is associated with a specific ticket. The image URL must not be empty and must start with either http:// or https://. The ticket the image is being added to must exist in the system. The same image URL cannot be added more than once to the same ticket, but the same URL may be added to different tickets. The manager can delete a ticket image from a ticket by specifying the image URL and ticket id. If the specified image does not exist for the given ticket, or if the specified ticket does not exist, the deletion request has no effect.

The manager can view the status of all maintenance tickets in the system. For each ticket, the view presents the ticket id, the ticket raiser, the date the ticket was raised, the description, and, if an asset is associated, the asset name, expected life span, purchase date, floor number, and room number. Each ticket also displays its associated maintenance notes showing the note taker, the date added, and the description, as well as its associated images showing the image URLs. Tickets with no notes show no notes, and tickets with no images show no images.
