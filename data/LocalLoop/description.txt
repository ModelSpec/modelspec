LocalLoop is a community event management platform that allows organizers to create and manage local events, participants to register for those events, and admins to manage event categories. The system supports three roles: Admin, Organizer, and Participant.

When a user creates an account, they must provide a first name, last name, username, email, password, confirm password, and whether they are an organizer. Phone number is optional. If the user is registering as an organizer, they must also provide a company name. The first name must not be empty, the last name must not be empty, the username must not be empty and must be unique in the system, and the email must not be empty and must be unique in the system. The email must contain an @ symbol, must have characters before the @, must contain a dot after the @, must have characters after the dot, and must not contain spaces. The password must not be empty, the confirm password must not be empty, and the password and confirm password must match. Upon successful account creation, a user ID is automatically assigned to the new account.

An account can be deleted by the account owner themselves or by an admin. A non-admin user cannot delete another user's account; attempting to do so raises an error stating that only admins or account owners can delete the account. If the requesting user does not exist in the system, an error is raised. If the target account to be deleted does not exist in the system, an error is also raised.

Categories are managed exclusively by admin users. An admin can create a category by providing a name and a description. The name must not be empty and the description must not be empty. Upon successful creation, a category ID is automatically assigned. Non-admin users, including Organizers and Participants, cannot create categories; attempting to do so raises an error stating that only admin users can update categories. An admin can also update an existing category's name and description, subject to the same validation rules that the name and description must not be empty. Non-admin users cannot update categories. Attempting to create or update a category using a non-existent account raises an error. Attempting to update a category that does not exist in the system raises an error. An admin can delete a category from the system. Non-admin users cannot delete categories; attempting to do so raises an error stating that only admin users can delete categories. Attempting to delete a category using a non-existent account raises an error. Attempting to delete a category that does not exist raises an error.

Organizers can create events in the system. When creating an event, an organizer must provide a name, description, fee, event start time, and event end time. A category ID and capacity are optional fields; if a category ID is provided it must correspond to an existing category. The event name must not be empty and the event description must not be empty. The fee must be 0 or a positive number. The capacity must be 0 or a positive integer. The event start time must not be empty and the event end time must not be empty, and the event end time must be after the event start time. Upon successful creation, an event ID is automatically assigned and the event is associated with the organizer who created it. Only users with the Organizer role can create events; non-organizers such as Participants cannot create events. Attempting to create an event using a non-existent account raises an error.

An organizer can update an existing event that they own. The same validation rules apply during an update as during creation: the name must not be empty, the description must not be empty, the fee must be 0 or a positive number, the capacity must be 0 or a positive integer, the start time must not be empty, the end time must not be empty, the end time must be after the start time, and any provided category ID must correspond to an existing category. Only users with the Organizer role can update events. An organizer can only update events that belong to them; another organizer cannot update an event they do not own. Attempting to update a non-existent event raises an error.

An organizer can delete an event that they own. Only users with the Organizer role can delete events; a non-organizer attempting to delete an event receives an error stating that only organizers can delete events. An organizer attempting to delete an event that does not belong to them receives an error stating that only the event organizer can delete the event. Attempting to delete a non-existent event raises an error.

Participants can register for events in the system. When a participant registers for an event, a registration is created with a status of pending, a timestamp provided at the time of registration, and the registration is associated with both the participant and the organizer of the event. A registration ID is automatically assigned. Attempting to register using a non-existent participant ID raises an error. Attempting to register for a non-existent event raises an error.

Registration statuses can be updated by the event organizer or by the participant who owns the registration. The valid statuses are pending, approved, and cancelled. A registration that currently has a status of approved or cancelled cannot be updated; attempting to do so raises an error indicating the registration cannot be updated due to its current status. A participant who is not the organizer and not the registration owner is not authorized to update the registration. Attempting to approve a registration when the event is already at full capacity raises an error stating that the registration cannot be approved because the event is at full capacity. Attempting to update a registration with an invalid or empty status raises an error stating that the status must be pending, approved, or cancelled. Attempting to update a registration using a non-existent user ID raises an error stating that the user ID is invalid. Attempting to update a non-existent registration raises an error stating that the registration ID is invalid.
